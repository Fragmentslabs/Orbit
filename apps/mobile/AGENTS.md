## Done
- Fragments (`app/(main)/fragments/index.tsx` list, `[id].tsx` viewer, `FragmentCard` in the chat, "Fragments" in the sidebar): the pages the agent builds, used on the phone. Creating and editing stay in the chat. The desktop serves each fragment under a signed address (`/api/file/fragment/<id>/<token>/`, scope `fragment`) with the same closed CSP as its scheme, wrapped in a host page (`__orbit-host.html`: an iframe + a courier). The page's `window.orbit` calls go app → WS `fragments:call` → the desktop's own broker (declared AND granted rule, budgets): the phone never grants anything. WS `fragments:list` / `fragments:pin`, and `fragments:changed` reloads the list and the open page (revision). The list cards show a picture of the page (`FragmentThumb`): the desktop takes it once per revision and theme (an offscreen window loading the host page in `cover` mode, where the page may only read `orbit.store`) and serves it as `__orbit-cover-<theme>.png`; the phone keeps it on disk through expo-image, keyed by fragment, revision and theme. Pin ("Fixar") is one flag in the manifest (`pinned.list`), the same on the desktop's gallery and the phone's list, independent of the sidebar and panel pins and with no mark on the card: pinned ones are just on top (hold a card on the phone for "Pin" or "Delete", the latter through WS `fragments:remove`; on the desktop it is an item of the card's menu; the pin travels through WS `fragments:pin`). Permissions are ported: an ask bar over the page while it wants something not allowed (AI, models, internet with its hosts, MCP with its tools, notifications) and a Permissions sheet with a switch per capability, through WS `fragments:grant` (the desktop tab's own grant function: an unreviewed import cannot be switched on, turning notifications off cancels what was scheduled) and `fragments:permission-ask` when the page asks again. Not covered: the microphone, forwarding the page's console to the agent, a per-fragment storage origin (every fragment shares the companion's origin for `localStorage`; `orbit.store` is the desktop's)
- Project screen in one place (`app/(main)/files/index.tsx`), like the desktop's panel: a bottom tab bar with Files (`FilesTab`), Changes (`ChangesTab`: list, diff, commit box that stages everything) and Commits (`CommitsTab`: log in pages of 30, refs, pushed/local, per-file diff); under the title the worktree and branch pickers (`WorktreeSheet` over the shared `WorktreeList`, `BranchSheet`) and the pull / push buttons (`RepoBar`). Through the companion WS `git:log|commit-diff|info|commit|pull|push`, `worktree:list|create|remove` and `sessions:set-directory` (switching worktree points the chat's folder at it; refused while the chat runs). The ⋯ menu has one "Files & git" item (its old Folder and Branch items were redundant with the "+" sheet's "Folder & branch" page). That page now also lists the worktrees (the same `WorktreeList`; switching one just changes the chat's folders) and no longer has the known-folders block. A folder without git shows a card with "Start repository" (`git:init`; the desktop's Changes view has the same empty state, no more raw git error). Not done: per-file staging (the desktop commits everything too), branch delete/merge, worktree "delete branch" switch
- Document viewer (`components/documents/DocumentViewer.tsx`, opened from the document card and from `#orbit-source/docN/pPLx-y` citations): full-screen WebView over the desktop's own HTML preview (generated documents) or over the source text drawn by the phone (`GET /api/documents/:id/text?sessionId=`, cited lines marked and scrolled to; an uncited .docx uses `GET /api/documents/:id/html`), with outline from headings, find-in-document, zoom (pinch + buttons) and the system share sheet. A PDF opens in "Original" mode like the desktop (`GET /api/documents/:id/pages`: page images + text positioned as fractions, drawn in a WebView with a transparent selectable text layer, the cited stretch marked, find over the loaded pages, outline); Markdown sources and agent-written documents are drawn as rendered Markdown in the app theme ("Document"/"Text" toggle). Not covered: print, find over pages that were never loaded (it prefetches the first 40)
- Start screen like the desktop's (`ChatScreen`, `StartSuggestions`, `CapabilitiesSheet`): the greeting drawn per opening (with the name the desktop learned, `GET /api/start-context`), its subtitle, a quiet "What does Orbit do?" link that opens the capability guide, and below either "Resume" (the last conversation, alone) or two capabilities side by side. The rule is the desktop's own, shared in `@orbit/shared` (`buildStartSuggestions`, `CAPABILITIES`, `pickWelcomeTitle`); tapping fills the composer, it never sends
